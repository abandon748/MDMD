# 开发与换机指南

本指南适用于当前 MDMD 0.2.0 的 Windows x64 开发。源码仓库根目录是包含 `package.json` 的 `MDMD` 文件夹；所有构建、测试命令均在这个目录运行。项目没有要求安装在特定盘符或使用特定 Windows 用户名。

## 1. 新电脑准备

| 工具 | 要求或当前参考环境 |
| --- | --- |
| Git | 安装 [Git for Windows](https://git-scm.com/install/windows)，用于版本管理与同步 |
| Node.js / npm | 当前参考版本为 Node.js 24.16.0、npm 11.13.0；部分规则测试直接运行 TypeScript，使用 Node.js 24 系列 |
| Rust / Cargo | 当前参考版本为 1.99.1，目标为 `x86_64-pc-windows-msvc`；通过 [rustup](https://www.rust-lang.org/tools/install) 安装 |
| C++ 工具链 | Visual Studio 2022 或相应 Build Tools，勾选“使用 C++ 的桌面开发”、MSVC x64/x86 编译工具及 Windows SDK；不必安装完整 IDE |
| WebView2 Runtime | 130 或更新版本；由 Windows 共享运行时提供 |
| 编辑器 | 自行选择，构建不依赖某一款编辑器 |

Windows 系统依赖安装入口见 [Tauri 官方指南](https://v2.tauri.app/start/prerequisites/)。当前应用包含 Windows 原生接口与安装逻辑，macOS、Linux、Windows ARM64 尚未作为本项目可用开发环境验证。

安装后重新打开 PowerShell：

```powershell
git --version
node --version
npm.cmd --version
rustc --version
cargo --version
rustup show active-toolchain
```

若 Rust 默认工具链不是 MSVC，可用 `rustup default stable-msvc` 设置。需要复现当前参考版本时，在工程目录执行 `rustup toolchain install 1.99.1-x86_64-pc-windows-msvc`，再执行 `rustup override set 1.99.1-x86_64-pc-windows-msvc`。该 override 是本机配置，不会随 Git 自动传到另一台电脑。

## 2. 获取源码与目录布局

仓库尚未上传，当前没有可用的项目远程地址。发布后将下面地址替换为实际地址；私有仓库需先完成 GitHub 登录授权。首次 clone 的目标目录必须不存在或为空。

```powershell
git clone https://github.com/YOUR_ACCOUNT/MDMD.git "D:\develop\MD\开发工作区\MDMD"
Set-Location -LiteralPath "D:\develop\MD\开发工作区\MDMD"
```

暂不使用 GitHub 时，也可以从旧电脑复制源码到相同层级的目录。带上 `.git` 才会保留本地 Git 历史；`node_modules`、`dist`、`src-tauri/target` 和 `test-results` 可不复制。未跟踪或被忽略的个人文件需要单独决定是否迁移。

现有发布约定如下，可更换盘符与最外层目录名称：

```text
MD/
├─ 开发工作区/
│  └─ MDMD/             # Git 仓库；在这里运行 npm
│     ├─ package.json
│     ├─ src/
│     └─ src-tauri/
└─ release/             # 构建生成，不属于 Git 仓库
```

**打包输出固定为项目根目录的 `../../release`。** 这是相对目录规则，不是固定到 D 盘。避免把仓库克隆到磁盘根目录或与其他项目共用同一个输出位置；打包会更新该目录中同名程序和安装包。安装器与发布测试使用同一约定。现有欢迎示例如果已存在会保留，因为它可能被用户编辑过。

## 3. 恢复依赖并启动

```powershell
npm.cmd ci
npm.cmd start
```

`npm ci` 按 `package-lock.json` 恢复前端依赖；Cargo 首次构建会下载 Rust 依赖。保留 `package-lock.json`、`src-tauri/Cargo.lock` 和 `config/engines.lock.json`，不要为解决下载失败而删除锁文件或随意升级依赖。项目内已声明 Tauri CLI，不需要额外全局安装。

第一次安装、编译和打包需要网络访问 npm、Rust/Cargo 以及 Tauri 打包工具下载源。应用的可选高亮、公式与图表资源由设置中的资源管理入口按固定清单下载；它们不等于构建依赖，也不需要从旧电脑复制到源码仓库。

开发程序启动后，先用测试用 Markdown 验证打开、编辑和保存。`npm start` 启动的是开发程序，不会安装正式安装包。

## 4. 检查与打包

关闭正在运行的开发程序后，执行基本检查：

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd test -- --locked
```

需要验证真实桌面交互时执行 `npm.cmd run test:ui`。它会启动应用、操作原生对话框并使用独立测试数据，运行期间避免操作测试窗口。证据位于被 Git 忽略的 `test-results/`。其他专项入口见根目录 README 与 `package.json`；部分专项使用 `--offline`，必须先完成在线依赖恢复。

打包及核对产物：

```powershell
npm.cmd run package
powershell.exe -NoProfile -File tests/release-artifacts.ps1
```

生成 `../../release/MDMD.exe`、版本化安装 EXE、便携 ZIP、使用说明、项目 GPL v3 `LICENSE`、第三方许可和 `SHA256.txt`。首次打包由 Tauri 下载所需 NSIS 工具。当前发布未做代码签名。

`tests/installer.test.mjs` 会实际安装、升级和卸载测试应用，并在发现已有 MDMD 安装登记时拒绝运行；仅在专用测试环境手动执行，不作为换机的第一步。新电脑成功编译不等于已经通过安装器、性能或完整 UI 验收。

## 5. 两台电脑继续开发

每台电脑分别配置 Git 提交身份；邮箱可以使用 GitHub 设置中提供的 noreply 邮箱：

```powershell
git config user.name "YOUR_NAME"
git config user.email "YOUR_COMMIT_EMAIL"
```

这些配置只记录提交作者，不是 GitHub 登录凭据。建议使用 Git Credential Manager 的登录流程，或在新电脑生成独立 SSH 密钥并登记到 GitHub。不要把 Token 或私钥写进仓库。

离开旧电脑前，先审阅改动，再提交与推送；以下假设已经配置远程仓库：

```powershell
git status
git diff
git add .
git diff --cached --stat
git diff --cached
git commit -m "Describe the change"
git push
```

在另一台电脑开始前，确保本地修改已妥善保存：

```powershell
git status
git pull --ff-only
npm.cmd ci
npm.cmd start
```

`pull --ff-only` 若因两台电脑分别产生提交而失败，应先处理分支合并，不要直接强推或执行 `reset --hard` 丢弃工作。只有提交且推送的内容会从远端同步；本地 Git 提交本身不是异地备份。

## 6. 单独备份的内容

- 个人 Markdown、附件和自定义素材：由你管理，不属于项目源码。
- 应用设置、历史和收藏：关闭 MDMD 后，可单独备份 `%APPDATA%\local.mdmd.markdown`；路径换机后可能失效，需要重新选择。
- 未提交的源码与仓库外的工作笔记：迁移前检查，不能只复制已发布安装包。
- 本地 `.env`、代理配置、签名证书等：如将来使用，单独安全配置；本项目当前构建不要求 API Key 或在线服务账号。
- 外层 `README/` 管理文档、参考截图、分析材料和版本归档：属于本地开发资料，按需要单独搬迁；源码构建不依赖这些目录。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| PowerShell 禁止运行 npm.ps1 | 使用本文的 `npm.cmd`，无需为此关闭系统执行策略 |
| 找不到 package.json | 进入仓库根目录，不要在外层 MD 目录执行 npm |
| 找不到 cargo / rustc | 安装 rustup 并重开终端；项目脚本默认从用户目录的 `.cargo/bin` 找 Cargo |
| 链接器、MSVC 或 Windows SDK 缺失 | 用 Visual Studio Installer 补装 C++ 桌面工作负载及 SDK |
| 首次构建网络失败 | 检查下载源和网络配置后重试，保留锁文件 |
| 找不到发布 EXE | 先打包，再检查项目根目录上两级中的 release；不是仓库内 release |
| 运行缺少 WebView2 | 安装或更新 Evergreen WebView2 Runtime |
| 换机后 Git 推送失败 | 重新配置 GitHub 身份验证；提交邮箱不能代替登录 |

## 8. 修改代码时的基本约定

修改 `src`、`src-tauri/src`、配置或脚本，不编辑生成的 `dist`、`target`、`gen`。保持文档归属、revision、磁盘冲突、备份与失败保护；不要把预览 DOM 直接作为整篇 Markdown 保存。预览不得获得任意脚本、Shell 或文件系统权限。

测试使用隔离数据，不能拿用户原文做破坏性验证。Markdown 文档统一 CRLF、UTF-8；Git 属性会在检出时保持 CRLF。任何测试结果必须注明实际执行范围，不用历史验收代替本轮结果。
